# mixed-signal-rtl-lab

**数模混合芯片「数字部分」的 RTL 实现与验证**：SAR ADC 时序控制器、旋变数字转换（RDC）跟踪环路、
互补 PWM 死区发生器、SPI 配置寄存器堆，以及把它们拼成一个小系统的顶层。

全部用**开源 EDA 工具链**（Icarus Verilog 仿真 + Yosys 综合）跑通，
并且每个模块都有**自检测试台**与**独立的 Python 定点参考模型**逐值比对。

> ⚠️ **先说清楚这是什么**
> 本项目是**个人自建的 RTL 设计与验证实践项目**，不是任何公司的产品代码，
> **没有流片、没有走过 ASIC 后端流程、没有用商业 EDA**。
> 模拟部分（比较器、CDAC、旋变前端、栅极驱动）都由**理想模型**代替，
> 目的是把**数字侧**的时序、协议、定点算法与验证方法做扎实。
> 不做什么、边界在哪，见文末[「边界与已知限制」](#边界与已知限制)。

---

## 为什么做这个

数模混合芯片里数字部分的活，跟纯数字 ASIC 很不一样：它往往不是"做一个大 SoC"，
而是**替模拟侧守住时序与安全**——采样窗口差一拍、死区少一个周期、定点移位错一位，
都可能让芯片在硅上直接失效。本项目就挑了四件最典型的事：

| 模块 | 数字侧要解决的问题 |
|---|---|
| `sar_adc_ctrl.v` | 逐次逼近的节拍、比较器结果的采样与判决、增益/失调的数字校准与饱和 |
| `rdc_tracking.v` | 由旋变 sin/cos 解出角度（Type-II 跟踪环路），并给出速度与锁定指示 |
| `pwm_deadtime.v` | 互补 PWM 的**死区插入**，非法配置直接进安全态（不能靠模拟侧兜底） |
| `spi_regfile.v` | 芯片的串行配置口：读写方向位、寄存器映射、状态回读 |
| `ms_top.v` | 把上面四块拼成一个可配置的数字子系统 |

## 快速开始

```bash
# 依赖：Icarus Verilog（仿真）+ Yosys（综合）+ Python 3（参考模型）
#   Ubuntu:  sudo apt-get install iverilog yosys
#   Windows: iverilog + oss-cad-suite（注意 bin 与 lib 都要进 PATH）

python tools/golden.py            # 生成正弦查找表与测试向量（含独立参考模型的期望值）
python tools/run_tests.py         # 跑全部 5 个自检测试台
python tools/run_tests.py --synth # 再跑一遍 yosys 综合并产出资源报告
python tools/run_tests.py --vcd   # 额外导出波形（build/*.vcd）
```

## 验证方法：为什么每个模块都要有独立参考模型

定点 RTL 最容易出的问题是**位宽、移位方向、饱和方式**写错。
这类错误的特点是：**仿真照样跑得动，波形看着也"像对的"**——
环路收敛了、PWM 有输出了、SPI 读回了数据，只是数值悄悄偏了几 LSB 或者整字节左移一位。

所以本项目采用**双轨验证**：

1. **Python 定点参考模型**（`tools/golden.py`）用**与 RTL 完全相同的整数运算**算出期望值；
2. 测试台把这些期望值当作**黄金参考**，逐值（RDC 的斜坡测试是**逐拍**）比对。

```
golden.py ──► rtl/sincos_rom.vh    （正弦表，RTL 与模型共用）
          └─► tb/vectors.vh        （输入向量 + 期望值）
                    │
   tb_*.v ──────────┘  自检测试台：驱动输入 → 逐值比对 → 统计错误数
                    │
   run_tests.py ────┘  一键跑全部 + yosys 综合，非 0 退出即 CI 红
```

## 实测结果

> 环境：Icarus Verilog 12.0 + Yosys 0.66（Windows 本地）/ Ubuntu CI；
> 数字全部来自 `python tools/run_tests.py --synth` 的真实输出。

**5 个自检测试台全部通过（`ALL TESTS PASSED`，错误数 0）**，覆盖约 **470 项逐值比对与断言**：

| 测试台 | 覆盖内容 | 关键结果 |
|---|---|---|
| `tb_sar_adc_ctrl` | 11 组输入码 × 2 组校准参数 + 时序 + 背靠背 | 原始码与校准码**全部与参考模型一致**；采样窗口 4 拍、转换 24 拍（12 位 × 2 拍）**精确匹配** |
| `tb_pwm_deadtime` | 两组配置 + 非法配置 + 使能关闭 | 4 个周期内**上下桥臂重叠 0 拍**；死区实测 h↓→l↑ 与 l↓→h↑ **都等于配置值**；非法配置进安全态并上报 |
| `tb_spi_regfile` | 16 位寄存器读写、有符号寄存器、CTRL 脉冲、只读状态、未映射地址 | 读写回读一致；`adc_start` 为**单拍脉冲**；有符号失调位扩展正确（-20） |
| `tb_rdc_tracking` | 12 个静态角度（含四象限边界）+ 400 拍斜坡 | 静态误差 **≤1 LSB**（65536 = 360°，即 ≤0.0055°），收敛 **12~15 拍**；斜坡 **400 拍逐位一致** |
| `tb_ms_top` | 系统级：SPI 配置 → 三路外设 → 状态回读 | ADC 回读 2500 精确匹配；RDC 锁定后角度回读**误差 0 LSB**；非法配置上报故障位并进安全态 |

**RDC 环路的实测指标**（`tools/golden.py` 输出）：

| 指标 | 数值 |
|---|---|
| 静态角度误差 | **≤ 1 LSB**（1 LSB = 360°/65536 ≈ 0.0055°） |
| 静态收敛拍数 | **12 ~ 15 拍**（含象限捕获那一拍） |
| 斜坡跟踪稳态滞后（64 LSB/拍） | 63 ~ 64 LSB（≈ 1 拍） |
| 锁定判定 | 连续 16 拍误差 ≤ 4 LSB 才置 `locked` |

**Yosys 通用综合（`ms_top`，techmap + abc，未绑定工艺库）：**

| 模块 | 门级单元数 | 说明 |
|---|---:|---|
| `rdc_tracking` | **9,162** | 正弦查找表（257×16 bit）+ 插值乘法 + 环路滤波占绝大部分 |
| `sar_adc_ctrl` | 1,280 | 12 位 SAR 寄存器 + 校准乘加与饱和 |
| `pwm_deadtime` | 480 | 比较器与死区逻辑 |
| `spi_regfile` | 453 | 移位寄存器 + 寄存器堆 + 读多路选择 |
| **合计 `ms_top`** | **11,377** | 其中 DFF/DFFE 共 329 个，其余为组合逻辑 |

> 📌 **综合结果本身就是一条设计反馈**：RDC 占了全系统 80% 的面积，
> 而其中绝大部分是那张正弦表。真实芯片里这里会换成更小的表 + 插值、
> 或者干脆上 CORDIC 把 ROM 换成移位加法 —— 这是本项目明确**没有做**的优化。

## 开发过程中被测试抓出来的真问题

这部分是项目里最有价值的内容：**下面每一条都是"仿真能跑、波形像对的、但结果是错的"**。

1. **乘法位宽陷阱（最典型）**
   Verilog 里乘法结果的位宽 = `max(操作数位宽)`，**不是两者之和**。
   RDC 的 `diff * ERR_SCALE` 写进 32 位上下文时静默回绕（`diff` 可达 ±2³⁰，乘 10430 需要 44 位），
   表现为**环路增益几乎为 0、角度一拍只挪 1 LSB**。
   是「斜坡 400 拍逐位比对」把它抓出来的 —— 只看"收敛了没有"根本发现不了。
   → 中间量必须显式给足 64 位（`rtl/rdc_tracking.v` 有注释标注）。

2. **正弦查找表不插值 → 误差被量化成 64 LSB 台阶**
   一开始只用 `idx = angle>>6` 查表，估计用的 sin/cos **每 64 个角度 LSB 才更新一次**，
   误差信号因此是台阶状的：环路无论怎么调参都只能收敛到 **±32 LSB**，
   而且台阶内误差恒为 0、积分器只会单向漂移。
   → 加线性插值后误差恢复成 ≈Δθ，静态误差从 ≥32 LSB 降到 **≤1 LSB**。

3. **Type-II 跟踪环路在 180° 偏差处锁不上**
   误差信号是 `sin(θ−φ)`，初始偏差正好 180° 时它**恒等于 0**，环路永远不动。
   这不是参数没调好，而是这类环路的固有性质。
   → 增加**象限预置**（按 sin/cos 符号把初值放到 ±45° 以内）后全部象限都能收敛。

4. **大偏差时积分器灌满退不下来**
   瞬态期间误差饱和，积分器一路累加到很大的值；等角度接近目标后误差变小，
   积分器却要用很久才能退回去，表现为**围绕目标缓慢漂移**。
   → 加抗积分饱和（|误差| 超过门限就冻结积分器）。

5. **采样使能做成寄存器 → 采样窗口少一拍**
   `sample_en` 原本是 `state == S_SAMPLE` 的寄存器版本，比状态晚一拍，
   `CLK_DIV=4` 实测只采样了 **3 拍**。→ 改成跟随状态的组合输出，实测 4 拍。

6. **SPI 读操作会把寄存器写成 0**
   一开始没有读写方向位，**读帧的数据字节是 0x00**，于是每次读都把目标寄存器清掉 ——
   读回来的值是对的，寄存器却已经没了。
   → 地址字节最高位定义为 R/W 位（1=读）。

7. **SPI MISO 移位早了一拍 → 主机读回整字节左移一位**
   地址字节后面紧跟的那个下降沿如果就移位，会把已经挂好的 MSB 顶掉。
   → 数据相位里等**第一个数据上升沿之后**才开始移位。

8. **函数返回值不能直接位选**（Verilog-2001 限制）
   `rd_value(rx_byte)[6:0]` 是语法错误，必须先落到 `wire`。
   这条不涉及算法，但直接让整个文件编译不过。

9. **测试台自身也会踩坑**
   ① 在 task 的 `while` 里统计时序，会**把只有 1 拍的 `dout_valid` 脉冲等过去**，
   结果 task 永远等不到它、仿真卡死；
   ② 在 `posedge` 采样计数会撞上非阻塞赋值的调度顺序，数出来少一拍
   → 统计挪到独立的 `always @(negedge clk)` 里。

10. **参考模型与 RTL 的顺序差一步**
    Python 模型里"先累加积分器、再用它算角度"，而 RTL 用的是**当前**（未累加）的值，
    两者差 1 LSB —— 逐位比对就是这么抓出来的。参考模型必须**逐语句对齐 RTL**。

## 边界与已知限制

**做过的**：4 个数字模块 + 1 个顶层子系统；自检测试台与独立定点参考模型；
逐值/逐拍比对；Icarus Verilog 仿真；Yosys 通用综合与面积统计；CI 一键回归。

**没做的 / 不能声称的**：

- **没有流片、没有 ASIC 后端**：没有综合脚本绑定工艺库、没有时序约束（SDC）、
  没有布局布线、没有 DRC/LVS、没有 DFT（扫描链 / MBIST / ATPG）、没有低功耗设计（UPF）。
- **没有用商业 EDA**：全程只有 Icarus Verilog 与 Yosys；
  Design Compiler / PrimeTime / VCS / Verdi / Innovus / Virtuoso **一个都没用过**，
  因此也**没有任何真实工艺下的时序（Fmax / 建立保持）数据**。
- **验证方法学是"自检测试台 + 黄金参考"，不是 UVM/SystemVerilog**：
  没有约束随机、没有功能覆盖率、没有形式验证。
- **模拟部分全是理想模型**：比较器没有失调/噪声/延迟，CDAC 没有电容失配，
  旋变前端没有滤波与相位误差，栅极驱动没有真实开关时序。
  **所以本项目的精度指标只反映数字侧算法，不代表整芯片精度。**
- **RDC 的角度分辨率受限于 16 位角度与 8 位查找表索引**：
  静态误差 ≤1 LSB 是数字环路的结果，真实 RDC 的精度主要由模拟前端与激励信号决定。
- **SPI 从机是简化实现**：sclk 只做了三级同步与边沿检测，
  没有输入去毛刺、没有 Schmitt 输入、没有超时保护；
  寄存器堆是行为级描述，没有做低功耗门控与时钟域优化。
- **面积数字是通用门级单元数**，不是任何工艺下的等效门数或面积（µm²）。
